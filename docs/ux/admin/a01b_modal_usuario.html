Por qué está así

  1. Modal sobre fondo atenuado: se abre al pulsar «Editar» en A1a o «+ Nuevo usuario». Permite hacer cambios rápidos de personal sin perder el contexto de la lista. En modo «Nuevo usuario», el título cambia a «Crear nuevo empleado» y la contraseña es obligatoria.
  2. Nombre completo: el nombre real de la persona. Se muestra en las cabeceras de los pedidos y comandas despachadas (ej. «Mesero: Miguel Angulo»).
  3. Nombre de usuario (login): es único en la base de datos (restricción UNIQUE en usuario.nombre_usuario). Si se intenta guardar uno repetido, el backend responde 409 USUARIO_DUPLICADO.
  4. Rol: selector exclusivo con los 5 roles definidos en el sistema: ADMIN, MESERO, COCINA, BAR, CAJA. Al iniciar sesión, el token Bearer emitido contiene este rol para el control de acceso en la API (CU2).
  5. Interruptor de estado (baja lógica): rellena la columna usuario.activo (booleano). Decisión D2: ningún usuario se borra con DELETE físico para garantizar la trazabilidad de auditoría de cuentas cerradas, pedidos y anulaciones.
  6. Restablecimiento asistido de contraseña (RF1): cumple con el requerimiento de que el administrador pueda desbloquear a un usuario que olvidó su clave, registrando un nuevo hash en el backend sin vulnerar la privacidad de contraseñas pasadas.
  7. Error USUARIO_DUPLICADO: mensaje oficial especificado en el SRS y en docs/02_api_y_eventos.md. Se resalta en borde punteado con fondo de advertencia.
  8. Botón «Guardar cambios»: ejecuta PATCH /usuarios/{id} (o POST /usuarios en caso de alta). Al completarse, cierra el modal y actualiza la lista A1a.
