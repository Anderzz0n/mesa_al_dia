Por qué está así

  1. Barra superior: muestra el rol «Administrador», el usuario en sesión (anderson), el estado de conexión con el WebSocket y la opción de cerrar sesión (que abre el diálogo de confirmación en A6).
  2. Pestañas principales: organizan las 5 áreas de responsabilidad de administración: Personal (usuarios y accesos), Sectores y Mesas (distribución y meseros), Menú (platos, bebidas, combos y opciones), Supervisión (actividad y recaudación) y Configuración (parámetros operativos).
  3. Pestaña activa: Personal. Lista los empleados dados de alta a través de GET /usuarios.
  4. Buscador en tiempo real: filtra la tabla localmente por nombre o por login.
  5. Filtro por rol: selector para ver solo Meseros, Cocina, Bar, Caja o Administradores.
  6. Botón «+ Nuevo usuario»: abre el modal de alta A1b para registrar nombre, usuario, rol y contraseña inicial (CU1, POST /usuarios).
  7. Tabla de usuarios: presenta los datos esenciales de gestión de personal. Se ordena alfabéticamente por nombre.
  8. Botón «Editar»: abre A1b cargando los datos del usuario para modificar su nombre, rol o activar/desactivar su acceso (PATCH /usuarios/{id}). El botón «Clave» permite el restablecimiento asistido (RF1).
  9. Detalle operativo: para los meseros muestra si tienen un sector asignado actualmente según `v_sector_vigente` (CU5), facilitando ver quién está de turno sin cambiar de pestaña.
  10. Fila inactiva (.off): un usuario con activo = false se dibuja en gris atenuado con etiqueta punteada INACTIVO. No se eliminan registros de la base de datos (decisión D2: no hay DELETE /usuarios para preservar la integridad de pedidos y auditoría). Si intenta ingresar, el sistema responde con USUARIO_INACTIVO (403).
