Por qué está así

  1. Modal de producto / combo: permite crear un plato regular o armar un combo promocional empaquetado (CU10, CU11, RF3).
  2. Selector de tipo: conmuta entre el formulario de producto individual (donde se elige destino físico COCINA o BAR, opciones y stock numérico) y el formulario de combo (donde se configura la lista de componentes).
  3. Nombre comercial: el nombre que ve el mesero en la carta digital y que se imprime en las comandas.
  4. Precio de paquete: el combo tiene un precio global consolidado ($ 28.000). Quitar un componente removible no reduce el precio del combo (regla estándar de restaurante).
  5. Regla de datos de combos (D3): en la base de datos (tabla producto), un combo tiene destino = NULL y stock_cantidad = NULL. Esta pantalla evita que el usuario introduzca datos contradictorios.
  6. Componentes del combo (tabla combo_componente): relaciona el combo padre con productos hijos preexistentes en el menú. Un combo no puede contener otros combos (regla del backend en `docs/00_contexto_para_continuar.md` línea 69).
  7. Casilla «¿Removible?» (CU11): marca la columna combo_componente.removible. Si está marcada, el mesero podrá marcarlo como quitado al personalizar el pedido para el cliente (ej. «sin papas»). Si un componente no removible se agota, el combo entero queda no disponible automáticamente.
  8. Guardar en catálogo: envía POST /productos o PATCH /productos/{id} guardando cabecera y componentes en una transacción.
