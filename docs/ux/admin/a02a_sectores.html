Por qué está así

  1. Barra superior: muestra el rol Administrador y mantiene consistencia visual con el resto del panel.
  2. Indicador en tiempo real: escucha en la sala admin del WebSocket el evento sector.asignacion para refrescar quién atiende cada sector sin recargar.
  3. Pestaña «Sectores y Mesas»: agrupa la gestión del espacio físico y la distribución operativa de los turnos de meseros (RF2).
  4. Subpestañas: separan la vista de Sectores y asignación (visión por zonas de trabajo) de la vista de Mesas y reasignación (visión individual de cada mesa en A2c).
  5. Botón «+ Nuevo sector»: abre el modal A2b para crear un sector nuevo y asociarle sus mesas iniciales (CU4).
  6. Tarjetas de sector: presentan de un vistazo el nombre del sector, la cantidad de mesas agrupadas y el mesero responsable. Una mesa pertenece a un solo sector a la vez.
  7. Asignación con vigencia (D4): se gestiona con PUT /sectores/{id}/asignacion. En la base de datos se guarda con vigente_desde y vigente_hasta (tabla asignacion_sector); al asignar un nuevo mesero, el backend cierra la asignación anterior automáticamente.
  8. Acción «Cambiar mesero»: abre un menú o diálogo rápido con la lista de usuarios con rol MESERO y estado ACTIVO. Un mesero puede tener varios sectores asignados simultáneamente si el aforo lo requiere.
  9. Alerta visual «Sin mesero asignado»: si un sector no tiene asignación vigente (o el mesero anterior terminó su turno), se resalta con borde punteado rojizo y botón primario para garantizar que ninguna mesa quede sin atención.
