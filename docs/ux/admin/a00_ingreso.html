Por qué está así

  1. Sin barra de pestañas, sin conexión y sin rol previo: antes de autenticarse no se conoce al usuario; la pantalla muestra el nombre del sistema y el formulario. El rol no se selecciona en el formulario: lo determina el token entregado por el backend (CU2). Al ingresar con rol ADMIN, aterriza directamente en A1a (Personal · Lista de usuarios).
  2. Usuario: nombre de acceso asignado en el sistema.
  3. Contraseña: enmascarada con puntos. No hay opción de «recordarme» por seguridad administrativa.
  4. Error CREDENCIALES_INVALIDAS (401): mensaje genérico para no revelar si el usuario existe o no en la base de datos.
  5. Error USUARIO_INACTIVO (403): la cuenta existe pero tiene activo = false. En el caso del administrador, otro administrador debe reactivar la cuenta.
  6. Botón «Ingresar»: envía POST /auth/login. En el wireframe enlaza a la pantalla principal A1a.
