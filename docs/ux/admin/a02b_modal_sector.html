Por qué está así

  1. Modal de sector (CU4): se abre desde «+ Nuevo sector» o «Editar sector». Permite definir la agrupación lógica de mesas para repartir el trabajo entre meseros.
  2. Nombre del sector: identifica la zona física (Salón, Terraza, Balcón, Barra, etc.). Tiene restricción de unicidad en la base de datos.
  3. Mesero responsable: campo opcional al crear o modificar el sector; si se selecciona, llama a PUT /sectores/{id}/asignacion tras guardar el sector.
  4. Error SECTOR_NOMBRE_REPETIDO (409): regla explícita del modelo y del SRS para impedir sectores homónimos que confundan el ruteo de pedidos.
  5. Error SECTOR_SIN_MESAS (422): regla de negocio estricta del backend (CU4 y `docs/00_contexto_para_continuar.md` línea 69: «un sector debe tener ≥1 mesa»). El botón de guardar se bloquea o muestra esta alerta si no hay al menos una mesa marcada.
  6. Selector de mesas: una mesa solo puede pertenecer a un sector. Si el administrador marca una mesa que antes pertenecía a «Terraza», la pantalla advierte que cambiará de sector.
  7. Guardar sector: ejecuta POST /sectores (o PATCH /sectores/{id} con las mesas seleccionadas). Emite el evento correspondiente y vuelve a A2a.
