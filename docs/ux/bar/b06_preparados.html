Por qué está así

  1. Lista de lo disponible a la izquierda (GET /preparados): es lo primero que el bar necesita saber, para no repetir un producto que ya está hecho (una jarra, un café). Agrupa por producto: una fila de la base de datos es una unidad, pero al bar le sirve el total.
  2. Estado vacío con el mensaje de CU20, adaptado: «No hay productos ya preparados». El SRS dice «platos»; Anderson aprobó «productos» para Bar (21/10/2026).
  3. Formulario a la derecha (POST /preparados, CU19): registrar unidades que sobraron o se hicieron de más. No hay que pasar por una comanda.
  4. Producto: se elige del menú con buscador. Solo productos con destino bar (DESTINO_NO_PERMITIDO si es del otro destino).
  5. Cantidad entera, mínimo 1: con − y +; no se aceptan decimales.
  6. Error de validación (tarea 9.6 del EDT: «valida contra el menú»).
  7. Aviso emergente cuando un mesero toma una unidad (evento preparado.asignado, que llega a la sala del área del producto): así el bar sabe que ya no está y no cuenta con ella. La lista de la izquierda se actualiza sola.

No hay forma de dar de baja una unidad registrada (por ejemplo, si se echó a perder): queda fuera de alcance (ver el mapa, pendientes). Las unidades que nacen de una cancelación las registra el sistema cuando caja marca crear_preparado.
